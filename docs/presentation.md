# 1. PSB Buddy — юридический ассистент

Порядок проверки: заполнить `.env` по примеру → `docker compose up --build -d` →
открыть http://localhost:3000 → задать вопрос по договору → открыть источник → проверить отказ.

Репозиторий: https://github.com/Axcellent/psb-buddy

Интерфейс доступен локально после запуска. Публичное развёртывание не заявлено.
Подробный порядок проверки: README.md и docs/CASE_COMPLIANCE.md.

# 2. Пользователь и проблема

Пользователь — юрист банка, проверяющий договоры и нормативные основания выводов.
Сейчас поиск по нескольким документам и уточнение редакций выполняются вручную.
Ассистент собирает ответ по базе и показывает, какие положения его подтверждают.
Ценность — сокращение ручного поиска при сохранении возможности проверить источник.
Эффект в минутах или процентах пока не измерен; численные улучшения не заявляются.

# 3. Архитектура и документы

React → Nginx /api → FastAPI → RAG → DeepSeek V4.1 Flash.
SQLite хранит чаты, историю и источники. Оба сервиса используют один ZIP базы.
BM25 строится при запуске; bge-m3 добавляет семантический поиск, если доступна.
Реранкер Qwen3 необязателен. Документы компании и законы разделяются при подготовке контекста.
Учебная база включена в репозиторий; реальные внутренние документы банка не используются.

# 4. Контроль достоверности

Генерация ограничена базой знаний: ссылки, даты, редакции, границы роли, исправление ложной посылки.
Отдельный вызов модели проверяет выводы и выбирает подтверждающие фрагменты.
Программа отклоняет неизвестные идентификаторы источников; случайные цитаты не подставляются.
Неподтверждённый ответ можно исправить один раз и проверить повторно.
Техническая ошибка не маскируется под отсутствие нормы или юридическое заключение.

# 5. Примеры по базе знаний

Ожидаемые примеры, а не результаты нового прогона:
Гарантия по договору с «Альфа-Трейд» — 24 месяца; открыть договор и соответствующее положение.
Аренда у «Северного Склада» — 450 000 рублей в месяц; уточнение в диалоге — до 5-го числа.
Размер пособия по беременности и родам — необходимых документов в базе нет; объяснить нехватку данных.
Вопрос о прошлой редакции закона — не переносить текущую норму на прошлую дату без основания.

# 6. Демонстрация интерфейса

Создать чат и задать вопрос. Показать ответ, документ, расположение и цитату.
Открыть документ: TXT/Markdown/DOCX показываются как текст, PDF — в PDF-просмотрщике.
Задать уточнение по предыдущему договору и показать сохранённую историю.
В новом чате проверить отказ и попытку смены роли; затем показать поведение при отказе сервиса.
Общий адрес фронтенда и API обеспечивает одинаковые ссылки при запуске через Docker.

# 7. Ограничения и проверка качества

После последних правок приложение, Docker и модель здесь не запускались по просьбе пользователя.
Качество, задержки и совместимость с прокси организаторов нужно подтвердить на стенде.
Проверка той же моделью снижает риск, но не гарантирует отсутствие фактических ошибок.
RAG читает TXT/Markdown/DOCX; PDF поддерживается для просмотра, но не для загрузки в поиск.
Ненулевой балл текущего сабмита и доступ жюри к приватному репозиторию проверяются перед сдачей.

# 8. Внедрение и развитие

Пилот — тестовая база и ограниченная группа юристов; результаты подтверждает специалист.
Метрики пилота: доля подтверждённых выводов, корректность отказов, полнота ссылок, время ответа.
Следующий этап — независимая проверка ответов, расширение набора проверок, измерение качества и задержек.
Для новой базы нужны контроль редакций, изоляция данных и согласованный порядок обновления источников.
Подготовка к сдаче: прогон сценария и ZIP, фиксация модели и версии кода, проверка доступа, репетиция защиты.
